## Core Principles & Rules

### 1. Data Management
- **NEVER hardcode portfolio content in components**
- All personal information, skills, experience, projects, and education data MUST be in `src/data/portfolio.ts`
- Components should import and display data from `portfolio.ts`
- When updating content, modify ONLY the data file, not components

### 2. Component Structure
- Use functional components with TypeScript
- Follow the existing section-based architecture
- Each major section should be in `src/components/sections/`
- Keep components focused and single-responsibility
- Use React hooks (useState, useEffect, custom hooks)

### 3. Styling Guidelines
- **Primary Framework**: Tailwind CSS with Tailwind v4 syntax
- **Custom Utilities**: Use `.container-custom` for consistent page padding
- **Dark Mode**: Use `dark:` prefix for dark mode styles (class-based dark mode)
- **Colors**: 
  - Primary: Blue palette (`primary-50` to `primary-900`)
  - Secondary: Gray/Slate palette (`secondary-50` to `secondary-900`)
  - Use `.text-gradient` utility for gradient text effects
- **Fonts**: 
  - Sans-serif: Inter (default)
  - Monospace: JetBrains Mono
- **Responsive**: Mobile-first approach, use `md:`, `lg:` breakpoints
- Avoid inline styles; prefer Tailwind utility classes

### 4. Animation Standards
- Use Framer Motion for all animations
- Common patterns:
  - `initial`, `animate`, `transition` props for entrance animations
  - Stagger animations for lists with delays
  - Smooth scroll behavior for navigation
- Keep animations subtle and professional
- Duration typically 0.3s-0.8s for normal animations

### 5. TypeScript Requirements
- All components must have proper TypeScript types
- Props should be defined with interfaces or types
- Use React.FC type for functional components
- No `any` types unless absolutely necessary
- Leverage TypeScript for data structure validation

### 6. Icon Usage
- Use Lucide React icons exclusively
- Import icons from 'lucide-react'
- Consistent sizing: `w-5 h-5` for small, `w-6 h-6` for medium
- Always include aria-labels for icon-only buttons

### 7. Dark Mode Implementation
- Dark mode managed by `useDarkMode` custom hook
- Persists preference in localStorage
- Respects system preference as default
- Toggle button in Header component
- All components must support dark mode with appropriate `dark:` classes

### 8. Navigation & Routing
- Single Page Application (SPA) with scroll-to-section navigation
- Use `id` attributes on sections: `#home`, `#about`, `#skills`, etc.
- Smooth scroll behavior with `scrollIntoView({ behavior: 'smooth' })`
- No external routing library needed (React Router not installed)

### 9. Performance Considerations
- Lazy load images when possible
- Optimize animations (use transform and opacity for GPU acceleration)
- Keep bundle size minimal - avoid unnecessary dependencies
- Use Vite's fast HMR for development

### 10. Code Quality
- Follow ESLint configuration (TypeScript ESLint with React rules)
- Use meaningful variable and function names
- Keep functions small and focused
- Add comments for complex logic only
- Maintain consistent indentation (2 spaces)

## Common Tasks

### Adding a New Project
1. Open `src/data/portfolio.ts`
2. Add new project object to `projects` array with all required fields:
   - id, title, description, longDescription, image, technologies, features, githubUrl, liveUrl, category
3. Add project image to `public/` folder
4. Component will automatically render the new project

### Updating Personal Information
1. Modify `personalInfo` object in `src/data/portfolio.ts`
2. Available fields: name, role, subtitle, phone, email, linkedin, github, portfolio, resumeUrl, bio

### Adding New Skills
1. Update appropriate array in `skills` object in `src/data/portfolio.ts`
2. Categories: frontend, backend, databases, tools
3. Each skill needs: name, level (0-100)

### Creating a New Section
1. Create new component in `src/components/sections/NewSection.tsx`
2. Add section to `App.tsx` in the appropriate order
3. Add navigation link to `Header.tsx` navItems array
4. Use consistent section structure with `id` attribute for navigation

### Modifying Styles
1. **Theme colors**: Update `tailwind.config.ts` extend.colors
2. **Animations**: Update `tailwind.config.ts` extend.animation and keyframes
3. **Global styles**: Modify `src/index.css`
4. **Component styles**: Use Tailwind utility classes in JSX

## File Conventions

### Naming
- **Components**: PascalCase (e.g., `Hero.tsx`, `Header.tsx`)
- **Utilities/Hooks**: camelCase with descriptive names (e.g., `useDarkMode.ts`)
- **Data files**: camelCase (e.g., `portfolio.ts`)
- **CSS classes**: kebab-case for custom classes, Tailwind utilities as-is

### Imports Order
1. External libraries (React, motion, lucide-react)
2. Internal components
3. Data/utilities/hooks
4. Types (if separate file)

Example:
```typescript
import React, { useState } from 'react';
import { motion } from 'framer-motion';
import { Mail, Github } from 'lucide-react';
import Header from './components/Header';
import { personalInfo } from './data/portfolio';

```

## Troubleshooting

### Dark mode not working
- Check if `dark` class is on root `<html>` element
- Verify `useDarkMode` hook is used correctly
- Ensure all dark mode styles use `dark:` prefix

### Animations not showing
- Verify Framer Motion is imported
- Check `initial`, `animate`, `transition` props are properly set
- Ensure viewport is not in reduced motion mode

### Build fails
- Run `npm install` to ensure dependencies are up to date
- Check TypeScript errors with `npm run build`
- Verify all imports are correct and files exist

### Tailwind styles not applying
- Ensure file is listed in `tailwind.config.ts` content array
- Check class names for typos
- Verify Tailwind version 4 syntax is used correctly
